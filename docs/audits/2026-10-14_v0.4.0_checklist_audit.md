# Spec Surgeon v0.4.0 checklist and reliability audit

The ordinary editing engine works across many tested cases, but this version has several consequential bugs. In particular, some wrong documents receive a PASS, preview approval does not bind the template, and certain CLI batch configurations can overwrite originals incorrectly. Fix the five priority findings below before relying on write-back for important specifications. These are reproducible failures, not requests for cosmetic perfection.

Audited October 14, 2026, America/Los_Angeles, at commit `3977ad9` on the workspace branch `work`. Application source and existing tests were left unchanged. The additions are this report, captured results, and six reproduction scripts. Every destructive test used disposable synthetic documents.

## Evidence and limits

- **Existing suite: 251 passed, 1 skipped**, in 76.26 seconds. The skipped test exercises real Windows Credential Manager. An initial run before the editable package installation failed seven isolated-subprocess imports; after installing the project correctly, the complete suite passed. Those setup failures are not product findings.
- **New checks:** 30 document-operation probes; 10 batch-safety probes; 9 offscreen GUI scenarios; 4 compiler/generated-transform probes; interruption, Strict-namespace, and 100-file tests; and independent template tests with actual PDF rendering. The GUI scenarios produced 5 passes and 4 expected failures, with those failures separately reproduced as ordinary test failures.
- **Real execution:** Python 3.12 on Linux; PySide6 6.12 offscreen; LibreOfficeDev 26.8.0.0.alpha0. Template field refresh and invisible-header findings were observed in rendered PDFs, not inferred solely from XML.
- **100-file batch:** all 100 good specs passed; two unreadable `.docx` files were isolated; five unwanted file types/lock files were ignored; originals stayed identical. Rendering was off. This measures small synthetic specs, not the time for a real 300-spec project.
- **Forced termination:** copies mode preserved all originals. Killing immediately before the atomic swap preserved the old document; killing immediately after it left one complete edited document and the remaining originals. No original was half-written. A kill before the swap leaves a temporary file; a killed run has no completed report/retry manifest.
- **Not exercised live:** Claude interpretation/API responses, Microsoft Word rendering/accept-reject, native Windows installation/update execution, Windows read-only attributes, real Credential Manager, OneDrive/SharePoint syncing, UNC shares, long Windows paths, multiple monitors, or native Windows 11 controls. No user project corpus or password-protected Word fixture was available. Scripted model responses test integration, not live model judgment.
- **Live update check:** attempted, but the environment proxy denied the GitHub API connection. The application classified it as an offline/proxy error. The suite verifies the up-to-date/error UI with fixtures; this audit does not establish the current published release.

Captured observations are in [the audit results](2026-10-14_v0.4.0_checklist_results.json). Temporary document/PDF paths in that file identify artifacts from this run; the scripts regenerate them.

## The checklist describes features missing from this checkout

This matters independently of the bugs. The workspace has only the prepared-template operation, `apply_header_footer_template`. It recognizes yellow-highlight and `{{NAME}}` slots. It does **not** implement automatic identification/replacement of an ordinary architect spec's number and title, and `match-template-spec-header-footer.json` is absent.

In a direct test, applying an ordinary `08 71 00 - DOOR HARDWARE` template to `21 13 13 / WET-PIPE SPRINKLER SYSTEMS` copied the architect's original header unchanged, with all executed checks passing and no flags. That is the generic copying operation's current behavior; it cannot substantiate the checklist's automatic personalization. A live compiler might correctly refuse that request, but was not tested. The specialized number-format, case-matching, title-substring and missing-anchor safeguards listed for that feature cannot be credited as implemented.

Likewise, the built-in font operations change **font names only**. No font-size parameter, size selector, or size-remapping operation exists. “Make 9 pt text 10 pt,” “Heading 1 Arial 11,” and matching a template's body font **and size** exceed this checkout's built-in capabilities. The existing catalog explicitly says size remains unchanged.

The suggested AI-generated “make PART headings bold” fallback is also overpromised: the independent verifier has no assertion family permitting that run-boldness change. Generating Python cannot add the missing verifier capability. It should remain unsupported until there is an independently verified operation for it.

Resolve the checklist/version mismatch before publishing those promises. The remainder of this audit applies to the exact checkout identified above.

## Five priority fixes

### F1 Duplicate output names can replace the wrong original

**P1, confirmed data loss through the library; also reachable from a multi-folder CLI batch.** Inputs `a/Spec.docx`, `b/Spec.docx`, and `c/Spec (1).docx` contain ALPHA, BRAVO and CHARLIE. The second file receives the generated output name `Spec (1).docx`, which collides with the third file's actual name. With one worker and write-back enabled, all three report PASS, but BRAVO's original is replaced with CHARLIE's document. Only two verification-record JSON files survive because record names also collide.

The allocator counts original filenames without reserving generated names; delivery later reads the now-overwritten output path rather than the bytes verified for that source. See [batch.py:293](../../src/spec_surgeon/batch.py#L293), delivery at line 411, and record writing at lines 440–450. The GUI's normal single-folder picker makes this less likely; the public CLI/library supports multiple input folders.

**Fix:** reserve unique output names across the entire batch, including literal names resembling generated suffixes and Windows case-insensitive collisions. Give records/plans/exceptions equally unique identities. Bind delivery to the verified output bytes or digest. Probe: `duplicate_output_names` in `audit_batch_safety.py`.

### F2 Copies mode can overwrite an input when output and source paths overlap

**P1, confirmed data loss through the library with a destination configuration also exposed by the CLI.** Put the selected input at `results/outputs/Spec.docx`, then run with `out_dir=results` and write-back **off**. The worker writes its edited output over that source. The later drift check notices the change and moves the same path into `failed/`, leaving the original input path missing.

[batch.py:154](../../src/spec_surgeon/batch.py#L154) writes before checking that output destinations are disjoint from inputs. This is not the ordinary timestamped GUI layout, but it defeats the copies-mode promise for a supported library/CLI invocation, including reprocessing previous outputs.

**Fix:** reject aliases between any input/template and every planned output before any write; account for resolved paths and filesystem aliases. Stage outputs in a separate directory. Probe: `output_overlaps_source` in `audit_batch_safety.py`.

### F3 Changing the template after Preview does not invalidate approval

**P1, confirmed through `gui.Session`.** Preview a prepared template, edit its static header wording from `MICROSOFT` to `UNREVIEWED OWNER`, then Run. The approval token is unchanged and the run delivers the new, unpreviewed wording with PASS.

[preview.py:32](../../src/spec_surgeon/preview.py#L32) hashes the spec and source file metadata but omits the referenced template bytes. [gui.py:176](../../src/spec_surgeon/gui.py#L176) accepts that token, then Run builds new plans against the changed template. The lower-level plan-to-apply template hash checks do work; they do not protect this preview-to-run gap.

**Fix:** include content identities for all external templates in preview approval and recheck them before running. Keep the per-plan checks too. Probe: `template_changes_after_preview` in `audit_batch_safety.py`.

### F4 A template title inside STYLEREF can be wrong even with rendering and PASS

**P1, confirmed in a rendered and delivered output.** The template contains a `{{SECTION_TITLE}}` slot inside a simple `STYLEREF "Heading 1"` field. The source section title is `WET-PIPE SPRINKLER SYSTEMS`; its first Heading 1 is `PART 1 GENERAL`. The operation fills the cached field result correctly but leaves the field instruction intact. The actual rendered header becomes **PART 1 GENERAL**.

The full batch delivers this document with rendering both off **and on**. In the latter case V6, V7 and V9 all pass. The header/footer-only comparison strips away the body's field dependency, so it does not establish that the full document displays the planned title.

See slot safety checks at [slots.py:139](../../src/spec_surgeon/ops/slots.py#L139), template validation at [apply_header_footer_template.py:274](../../src/spec_surgeon/ops/apply_header_footer_template.py#L274), and independent slot checks at [verify/template.py:535](../../src/spec_surgeon/verify/template.py#L535).

**Fix:** refuse fills inside field instructions/results, with independent verifier enforcement. Any future field-aware support must verify the full document's refreshed display. Probe: `styleref_slot` in `audit_template_probe.py --render`.

### F5 Removing the cover number can remove body numbers too

**P1, confirmed wrong output passing verification without rendering.** A two-section file has a PAGE field in its first footer and the body footer is “Link to Previous.” The cover-number operation accepts it and removes the shared PAGE field. Both cover and body lose numbering, while every executed verification check passes.

[fix_page_numbering.py:110](../../src/spec_surgeon/ops/fix_page_numbering.py#L110) tests only explicit references. An inherited body footer has no explicit reference, so it escapes the shared-footer guard.

**Fix:** resolve effective footer inheritance across sections before changing the cover footer; refuse if another displayed section uses the same part. Probe: `cover_footer_inherited_by_body` in `audit_ops_checklist.py`.

## Recommended order of work

1. Fix output identity/isolation and preview binding: F1–F3. Add regression tests that inspect the actual delivered bytes and surviving originals, not just verification status.
2. Fix wrong content/page-number behavior: F4/F5, then F9–F12. Independently assert document semantics; the current verifier often proves the plan was executed, while the plan itself is wrong.
3. Contain rendering, filesystem, profiling, advice and generated-transform failures per file. Publish only verified, current outputs and preserve a usable report when a run partly fails.
4. Align the checklist with this version. Implement missing architect matching and font-size support with proper verification, or mark them unsupported until they exist.
5. Run a focused Windows smoke test on disposable copies: Word installed and absent, actual locked/read-only files, real Word field refresh/accept/reject, Credential Manager, and a small synced-folder batch. Leave visual refinements until those pass.

Until the priority fixes land, use copies in a fresh results directory separate from every input, inspect the actual output documents, and do not treat PASS as proof that template fields or numbering mean what was requested. Rendering is useful, but F4 demonstrates it is not sufficient by itself.

## Reproduction

From the repository root, install the project into a disposable development environment with `python -m pip install -e '.[dev,gui,agent]'`. Editable installation is necessary because the generated-transform sandbox deliberately uses Python's isolated `-I` mode. No API key is needed for these probes.

```bash
QT_QPA_PLATFORM=offscreen SPEC_SURGEON_NO_UPDATE_CHECK=1 python -m pytest -q
python docs/audits/probes/audit_ops_checklist.py
python docs/audits/probes/audit_batch_safety.py
python docs/audits/probes/audit_template_probe.py --render
PYTHONPATH=src:tests QT_QPA_PLATFORM=offscreen python -m pytest -q -rx docs/audits/probes/audit_ui.py
python docs/audits/probes/audit_compiler_codegen.py
python docs/audits/probes/audit_runtime.py
```

The standalone scripts assert or record current observations, including defects; their successful exit does **not** mean the application meets the desired behavior. The four strict GUI xfails similarly document known failures. Convert the relevant cases to desired-behavior regression tests when fixing them. The template `--render` probes require LibreOffice; the Windows-specific claims still require Windows.
