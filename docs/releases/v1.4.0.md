# Spec Surgeon 1.4.0

Includes all changes merged since v1.3.0, including PR #44 and the "ez mode" round
(`docs/PLAN-2026-10-19-ez-mode.md`): the desktop is one product, the window describes
its plan in plain sentences, and a mixed batch gets one plan per layout.

## Installing and updating

- Existing installations: choose **Help → Check for updates…**, then **Install now**.
- Windows: download `SpecSurgeon-1.4.0-Setup-x64.exe` from this release and run it.
- Python: install `spec_surgeon-1.4.0-py3-none-any.whl`; add `[gui]` for the window
  and `[agent]` for typed requests. Checksums are in `SHA256SUMS`.

## What you see

- One window: attach Word documents from any folders, optionally one template, and type the request. There
  are no pages, menus of workflows or modes; **Help** keeps update checks, the diagnostic logs and About.
- Every attachment is checked the moment it is added, in milliseconds and without a model call. One line under
  the file says what was found: typed numbers, no paragraph styles, text boxes in headers or footers,
  compatibility mode, editing restrictions, pending tracked changes, comments, irregular spacing. A file that
  does not open as a Word package or has no body text is refused with a sentence and never enters a plan;
  `.docm`, `.doc` and lock files are not attached.
- **Here's what will change** lists one sentence per change, written by the operation itself (every operation
  now has `describe()`), in inches and points, with assumptions inline and every setting one click away.
- A batch whose documents are built differently gets one specification per structural layout: one card per
  layout ("Layout label · N documents"), each validated and previewed on its own documents, one approval. A
  document no layout covers is listed under **Left untouched** with the reason, before anything runs.
- Clarifications are buttons; typing a number or your own words also works. Recovery of files that failed a
  check and custom methods run internally and end in the same single action, **Create edited copies**. After a
  plan per layout, recovery takes one layout at a time, each against its own specification; the other layouts
  wait and follow once the first layout's copies are saved.
- Progress, elapsed time, estimated spend, **Stop after current step**, the $10 allowance with an explicit
  **Allow another estimated $10**, and the saved conversation (`conversation.json` in the configuration
  folder) remain as before; attachments are checked again when a conversation is reopened.
- Normalizations (typed numbers, direct formatting, whitespace, pending revisions) are never automatic; they
  are only ever an explicitly offered first stage. The paragraph role classifier now feeds ordinary planning
  as per-layout evidence; it is never the authority for an edit.

## Removed

- The four-step window, its pages and dialogs, and the File menu items: built-in workflows, office profiles,
  spec QA audits, the operation browser, recovery workspaces, repair memory and the project evidence editor.
- Library offers in the conversation: recipes, operations and snippets are no longer offered by the model.
- PROJECT.json project memory in the conversation.
- Neighboring input-file discovery: tables and pictures beside the documents are no longer listed
  automatically. A specification can still name a file explicitly.
- The ordinary outcome review (`ordinary_outcomes.py`) and the `--outcome-review` / `--outcome-approval` flags
  of `run-spec`, `do` and `retry`.
- The legacy window images `docs/gui*.png`, replaced by `docs/conversation-start.png` and
  `docs/conversation-preview.png` (regenerated by the owner with `packaging/gui_screenshot.py`).
- `Session.folder`: the engine `Session` takes `documents=[...]`.

## The command line keeps

Every subcommand: `jobs`, `fingerprint`, `plan`, `run`, `ops`, `workflows`, `evaluate`, `evidence`,
`profile`, `audit`, `plan-spec`, `run-spec`, `do`, `retry`, `resolve`, `memory`, `chain`, `library`, `verify`,
`gui`, `advise`, `diagnose`, `workspace`, plus `structure` and `profiles`. Office profiles, spec QA audits,
project evidence, built-in workflows, campaign workspaces and recovery stay as command-line features.
`plan-spec` and `run-spec` accept a layout plan. The engine, the verifier and the records are unchanged.

## Validation and remaining acceptance

Publication is gated by the existing Linux and Windows test suites, including the dirty fixture family
(`tests/make_fixtures.py --dirty`), the triage, layout and describe tests, and the installed Windows app checks.

A live model run with its time and cost, the owner's private 12-specification corpus and template, and Word
rendering with visual acceptance remain pending on the owner's machine. No live-run diagnostics bundle or
private-corpus acceptance is claimed by this release.
