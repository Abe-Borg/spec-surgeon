# Spec Surgeon v0.7.1

Fill project variables, apply replacement tables, resolve options, reuse snippets and update
logos and filenames with built-in operations. Run several recipes as a verified chain, or
investigate failed requests with bounded recovery and local repair memory. This release
includes everything merged since v0.6.0, including the recovery review fixes.

## Installing and updating

- **From v0.4.x, v0.5.0 or v0.6.0:** choose **Help → Check for updates…**, then **Install now**.
  The app verifies the installer, closes, installs the update and reopens. Existing settings,
  library items and results are kept.
- **New installation or v0.3.x:** download `SpecSurgeon-0.7.1-Setup-x64.exe` from this release
  and run it. No administrator rights are needed.
- **Python:** install `spec_surgeon-0.7.1-py3-none-any.whl` from this release; add `[gui]` for
  the window and `[agent]` for Claude. Saved specs and library items run without an API key.

## Built-in edits and snippets

- Fill brace placeholders and highlighted fields from supplied values or CSV, TSV and XLSX
  tables. Apply multiple find/replace pairs in one pass and update issue stamps wherever
  they appear in the selected body, headers and footers.
- Resolve bracketed options by explicit rules and keep or delete paragraphs tagged for a
  system type. Ambiguous matches are set aside rather than guessed.
- Ensure each file ends with its own END OF SECTION line; make header/footer, title and
  filename values agree; name output copies using values extracted from their content.
  Colliding output names are set aside. Naming operations deliver copies only.
- Swap a supplied logo into the existing picture's space. Picture and table inputs are
  pinned by the preview and checked again before delivery.
- Save a paragraph in **Your library** as a snippet, then insert its exact words beside an
  anchor. Claude can offer a named snippet for you to choose.
- Each edit is predicted from the source and independently verified. Text edits default to
  tracked changes; clean copies are available with `tracked: false`. Operations place only
  approved wording or values read from supplied inputs and the document itself.

## Verified chains

- Run several EditSpecs or saved recipes in order with `spec-surgeon chain`. Each stage
  plans from its actual input and runs independent verification. A file that fails stops
  there; verified files continue. Changed intermediate bytes are refused.
- Chains retain per-stage records, a combined report and a set-aside manifest. Final copies
  retain names assigned by naming stages. Reusing a results folder clears old delivery
  outputs so files from an earlier run cannot appear as new successes.
- Conflicts between operations and the source properties they read are detected during
  planning, with guidance to split dependent changes into separate stages.

## Recovery and local repair memory

- Use **Investigate with recovery…** or **Resolve remaining files** in the window, or
  `spec-surgeon resolve` at the terminal, to investigate failed compilation, preview and
  batch or chain results. Set spending, attempt and call limits before starting.
- Recovery can inspect structure, XML, templates, input tables, pictures, diagnostics and
  rendered pages, then try revised extraction rules or verified sequences on copies.
  It preserves the approved goal, selectors and values; unsupported repairs remain unresolved.
- Independent final checks catch later stages undoing declared requirements. Ready copies
  require review and separate export, with fresh input and output checks. Recovery never
  writes over originals; blocking visual findings need explicit acknowledgement.
- An optional local repair database retains useful cases and failed approaches. Inspect,
  accept, reject or forget cases through **File → Repair memory…** or `spec-surgeon memory`.
  Reuse requires current applicability checks and fresh verification. Memory can be disabled;
  retained freeform text can include project details and relevant cases can be sent to Claude.
- The review fixes preserve default symbol-font exceptions and refuse final font requirements
  that recovery cannot independently represent. Each remembered case receives only the visual
  evidence for that candidate's verified outputs.

See [Recovery and local repair memory](https://github.com/Abe-Borg/spec-surgeon/blob/v0.7.1/docs/RECOVERY.md)
for usage, limits and privacy details. Custom recovery is opt-in and currently limited to
page-setup goals. Source-relative font requirements with preservation exceptions can remain
unsupported; recovery does not discard those exceptions to obtain a passing result.

## Validation and remaining limits

The release workflow gates publication on the Linux suite with Qt and LibreOffice, package
metadata and clean-wheel installation checks, Windows tests, and installed-app preview, run
and update checks. Tests use synthetic documents, scripted model replies and isolated settings;
they do not call the live API or touch your saved API key. Live Claude repair quality,
real-project success rates, actual API spending and Word COM fidelity remain separate validation
work, described in the [real-batch evaluation protocol](https://github.com/Abe-Borg/spec-surgeon/blob/v0.7.1/docs/RECOVERY_EVALUATION.md).
The installer, wheel and source archive are listed in `SHA256SUMS`.
