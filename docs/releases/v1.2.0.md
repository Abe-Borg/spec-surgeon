# Spec Surgeon 1.2

Spec Surgeon v1.2.0 includes all changes merged since v1.1.0, including PR #40:
reviewed office profiles, specification quality checks, project evidence and
runtime reliability improvements.

## Installing and updating

- **Existing v0.4.x or later installation:** choose **Help → Check for updates…**,
  then **Install now**. Settings, library items and results are retained.
- **New installation or v0.3.x:** download `SpecSurgeon-1.2.0-Setup-x64.exe` from
  this release and run it. No administrator rights are needed.
- **Python:** install `spec_surgeon-1.2.0-py3-none-any.whl` from this release;
  add `[gui]` for the desktop window and `[agent]` for Claude. Office profiles,
  built-in operations and report-only specification QA work without an API key.

## Reviewed office profiles

Open **File → Office profiles…** to create or import a portable office standard.
Profiles bundle original reference assets, explicit specification-role mappings
and optional policies. Analyze the selected documents, resolve uncertain paragraph
roles, approve the exact review, then preview and approve the evidence before
running verified copies. Each batch requires fresh approvals bound to its inputs.

The `replace_style_owned` formatting policy removes only eligible direct
properties supplied by the destination paragraph style or its ancestors.
Protected formatting and properties without clear ownership remain. Adjacent
reviewed targets are grouped without crossing excluded or unmapped paragraphs.

The same create, review, preview, run, import and export flow is available through
`spec-surgeon profiles`. See [office profiles](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/OFFICE_PROFILES.md)
for commands, approval requirements and conservative numbered-style limits.

## Specification review and project evidence

- `spec-surgeon structure` reports paragraph locations, structural roles and
  unresolved coverage without editing files. Spec QA adds duplicate-provision
  checks with numeric safeguards and internal-reference checks.
- The workspace's **Project facts and standards…** editor and `spec-surgeon evidence`
  commands retain scoped facts, assumptions, human confirmation and supersession
  history. Updating evidence invalidates the affected project's prepared results.
- A user-approved standards register supports report-only citation comparisons.
  Missing editions or conflicting entries stay unassessed; findings never
  authorize automatic wording changes.
- `add_review_comments`, the 51st built-in operation, inserts only explicitly
  supplied comment wording, source text and author at exact paragraph targets.
  Existing text, revisions and comment threads are preserved and independently
  checked. Comment outcomes currently require a separate approved stage.

See [specification QA](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/TEXT_HYGIENE_AND_SPEC_QA.md),
[project evidence](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/PROJECT_EVIDENCE.md)
and [review comments](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/EDIT_REASON_COMMENTS.md).

## Runtime reliability and evaluation

DOCX intake now bounds archive size, member counts and expanded content before
processing. Unchanged repacks retain the original bytes; changed archives preserve
supported package metadata and duplicate inert members, with independent checks.
Batch and retry workers explicitly use spawned processes to avoid inheriting Qt
state. Word rendering runs in isolated workers with deadlines, refuses stale PDF
results and limits cleanup to Word instances whose ownership can be proved.

Whole-workflow evaluation adapters compare actual batch, chain, campaign and
recovery reports, retain original source pins and distinguish automated checks,
provider measurements and human acceptance. See [runtime reliability](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/RUNTIME_RELIABILITY.md)
and [workflow evaluation](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/WORKFLOW_EVALUATION_V3.md).

## Packaging, validation and limits

The release workflow gates publication on Linux and Windows test suites, Qt and
LibreOffice checks, distribution metadata, clean wheel installation and installed
Windows app checks. The installer, wheel and source archive match the release tag
and are listed in `SHA256SUMS`; existing versioned installers remain immutable.

Regression coverage uses synthetic documents and scripted/offline provider
responses. It does not establish live-model quality, customer-project success
rates or human-accepted Microsoft Word appearance. Review representative client
files in Word before treating those outcomes as qualified. The
[qualification record](https://github.com/Abe-Borg/spec-surgeon/blob/v1.2.0/docs/audits/2026-10-18_office_profiles_and_spec_review.md)
records the feature-specific evidence and its limits.
