# Spec Surgeon v0.8.0

Manage several projects in a persistent workspace, resume document investigations, and use
expanded built-in operations for cleanup, styles, numbering, tables and text hygiene. Inspect
specification QA reports without changing a document. This release includes everything merged
since v0.7.1, including the workspace, numbering and conversion review fixes.

## Installing and updating

- **From v0.4.x or later:** choose **Help → Check for updates…**, then **Install now**.
  The app verifies the installer, closes, installs the update and reopens. Existing settings,
  library items and results are kept.
- **New installation or v0.3.x:** download `SpecSurgeon-0.8.0-Setup-x64.exe` from this release
  and run it. No administrator rights are needed.
- **Python:** install `spec_surgeon-0.8.0-py3-none-any.whl` from this release; add `[gui]` for
  the window and `[agent]` for Claude. Saved specs, library items and QA audits work without
  an API key.

## Persistent multi-project workspaces

- Open **File → Multi-project workspace**, or use `spec-surgeon workspace`, to inventory
  project folders recursively. Keep each project's facts, requests, templates and answers
  separate. Inspect provisional project assignments before setting goals.
- Generate a plan, review its exact document effects and wording, approve that plan, then
  run it. Built-in methods get a deterministic first pass. Independent final checks enforce
  the approved outcome even when an investigation changes its method.
- Reopen a workspace or recovery folder to continue with its evidence, attempts, questions
  and verified candidates intact. Ready documents remain available while others need work.
  Explicitly refresh sources repaired outside the app; changed goals or inputs invalidate
  dependent candidates. Saved status never bypasses current verification.
- Export verified copies separately. Originals remain untouched by workspace recovery.
  Blocking visual findings require fresh review after reopening; acknowledgements are
  never restored from disk.
- Agents can inspect paged evidence, render available pages, run isolated read-only analysis,
  and retain complete context archives. Custom methods remain constrained by approved
  effects, target counts and literal wording.

**Review model allowances before investigating.** Defaults are 50 candidate attempts per
problem group, 512 model calls, 64,000 output tokens per call, 20 million estimated total
tokens, maximum reasoning effort and **$250 estimated model spend per investigation**.
These are configurable ceilings. Projects have separate allowances; explicitly resuming an
investigation grants a new continuation allowance while retaining prior spending history.
Estimates can differ from the provider's bill. Inventory, saved progress inspection and
unambiguous approved built-in operations need no model call.

See [Adaptive workspaces](https://github.com/Abe-Borg/spec-surgeon/blob/v0.8.0/docs/ADAPTIVE_WORKSPACES.md)
for commands, approval, budgets and supported effect families.

## More built-in document operations

- **Cleanup and issue preparation:** remove selected comments or highlighting; accept or
  reject tracked changes by explicit instruction; remove hidden text, specifier notes,
  excess blank paragraphs, hyperlinks or watermarks; add a supplied watermark; unlink
  supported fields while preserving their displayed text; set document properties and
  requested tracking/final settings. Page-number fields remain protected.
- **Formatting and styles:** select runs by color, set tab stops, paragraph borders and
  shading, style spacing and proofing language. Clear direct formatting, apply styles by
  pattern or appearance, map styles from a supplied document and remove unused styles.
  Imported styles retain their required dependencies and list definitions.
- **Numbering:** convert numbering to a scheme from an example document; convert typed
  numbers to real list numbering only when the visible document still reads the same;
  adjust a level's format, zero padding, start and restart. Audit numbering gaps,
  duplicates and empty numbered paragraphs. Unsupported numbering is reported or refused.
- **Tables and sections:** set table borders, cell margins and width, repeat header rows,
  prevent rows splitting across pages, and apply a table style. Select sections by content
  for page setup, including landscape schedules and different-first-page behavior.

Each edit is predicted from source inputs and checked by an independent verifier. Changes
that depend on earlier edits belong in separate verified chain stages. No operation invents
document wording; revision resolution and document state changes require explicit requests.

## Text hygiene and report-only specification QA

- Normalize repeated/trailing spaces, explicitly chosen quote and dash styles, section-number
  separators and nonbreaking spaces around supplied units or section numbers. Plans show
  every exact character edit. Edits are tracked by default; fields and structural characters
  are protected.
- Review defined-term capitalization one occurrence at a time. Each picked proposal
  authorizes its exact change in one unchanged source; a broad request or another occurrence's
  approval does not authorize it.
- Open **File → Spec QA audits…**, or use `spec-surgeon audit`, to report placeholders,
  cross-references, standards citations, issue readiness and project identity variants.
  Export Markdown or JSON. Audits need no API key and never write an edited DOCX.
- Reports retain source locations and identify unreadable or incomplete evidence. Standards
  and editions are reported as written; latest editions and AHJ adoption are not inferred.
  A report with no findings is not issue certification.

See [Text hygiene and specification QA](https://github.com/Abe-Borg/spec-surgeon/blob/v0.8.0/docs/TEXT_HYGIENE_AND_SPEC_QA.md)
for exact choices, audit limitations and CLI examples.

## Expanded local diagnostics

Correlated event journals connect UI actions, model calls, previews, batch workers, independent
checks, recovery, delivery and reporting. They record timing and failure details and are
included in **Help → Save diagnostics bundle…**. Diagnostics stay local; this system does
not upload telemetry. Bundles exclude documents and page images, but reports and transcripts
can quote project text, so review bundles before sharing.

See [Investigating failures](https://github.com/Abe-Borg/spec-surgeon/blob/v0.8.0/docs/DEVELOPER_DIAGNOSTICS.md).

## Validation and remaining limits

Publication is gated on the Linux suite with Qt and LibreOffice, distribution metadata and
clean-wheel installation checks, Windows tests, and installed-app preview, run and update
checks. Tests use synthetic documents, scripted model replies and isolated settings; they
do not exercise the live API or touch saved API keys. Live model quality, real-project success
rates, actual API spending and Word COM fidelity require separate validation. See the
[real-batch evaluation protocol](https://github.com/Abe-Borg/spec-surgeon/blob/v0.8.0/docs/RECOVERY_EVALUATION.md).

The release preparation also corrects a renderer-test path assertion for Windows separators.

The Windows installer, wheel and source archive are listed in `SHA256SUMS`.
