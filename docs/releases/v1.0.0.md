# Spec Surgeon 1.0

Spec Surgeon 1.0 packages the latest merged work as v1.0.0. It includes all v0.8.0
capabilities, adds built-in workflows that run without an API key, broadens independently
verified workspace outcomes, and adds paired evaluation reports for measuring your own batches.

## Installing and updating

- **From v0.4.x or later:** choose **Help → Check for updates…**, then **Install now**.
  The app verifies the installer, installs the update and reopens. Existing settings,
  library items and results are kept.
- **New installation or v0.3.x:** download `SpecSurgeon-1.0.0-Setup-x64.exe` from this release
  and run it. No administrator rights are needed.
- **Python:** install `spec_surgeon-1.0.0-py3-none-any.whl` from this release; add `[gui]` for
  the desktop window and `[agent]` for Claude. Built-in workflows, saved specs, library items
  and specification QA audits work without an API key.

The package, installer and tag use the full version **1.0.0** so existing in-app updates
recognize the **1.0** release.

## Built-in workflows

Choose **Built-in workflows…** in the desktop or run `spec-surgeon workflows list`.
Four named starting points ship with the app:

- **Architect styles:** map named styles to a supplied office example, with optional unused-style
  removal in a separate verified stage.
- **Match numbering:** convert selected automatic numbering to an explicit example scheme.
- **Format tables:** apply a table style and then the selected layout properties.
- **Proofing language:** set Word's spelling metadata without changing document wording.

Configure the inputs, preview every stage, review and approve execution, then receive
independently verified copies. Loading a workflow does not execute it. Useful configurations
can be saved to **Your library** as chains. Source and template identity are checked again
before an approved run. Explicit `--in-place` execution retains the existing write-back guard.

See [Built-in workflows](https://github.com/Abe-Borg/spec-surgeon/blob/v1.0.0/docs/BUILTIN_WORKFLOWS.md)
for inputs, CLI examples, supported combinations and review requirements.

## Broader verified workspace outcomes

Workspace plans can now express paragraph styles, style mapping, proofing language, table
formatting and styles, automatic numbering and typed-number conversion. Page setup also
supports a different first page and selection by section content.

Each effect records explicit settings, selection rules, a source-bound target count and the
SHA-256 of any attached template. The independent verifier re-resolves the approved targets
against the original document and checks the final result. Changing a method never authorizes
extra edits or dropping a requested effect. Unsupported or overlapping combinations are
explained rather than silently approximated. Numbering whose display cannot be predicted
remains refused or flagged under the existing operation rules.

The default working-context allowance is now **900,000 estimated input tokens**, retaining more
evidence before archiving a conversation. `do` and `retry` honor `--max-context-tokens` and
`--max-output-tokens` in chat, noninteractive compilation and approved custom-transform handoffs.
Fit these settings to the selected model, leaving room for output and estimation error; the
default output allowance remains 64,000 tokens. Spending and other resource limits still apply.

See [Adaptive workspaces](https://github.com/Abe-Borg/spec-surgeon/blob/v1.0.0/docs/ADAPTIVE_WORKSPACES.md).

## Paired evaluation reports

Compare saved baseline and current recovery reports for the same pinned workload. The local
evaluator records completion, end-to-end time, human interventions and estimated model cost,
and keeps scripted, live-provider and unknown provenance separate. Report hashes, input
identities and approved outcomes must match the comparison's declared scope.

Human acceptance requires complete recorded judgments, visual review and a nonblank reviewer
name. Unreviewed or anonymous judgments do not count as accepted results. Unknown time or cost
stays unknown. The evaluator makes no provider calls, changes no documents or repair memory,
and does not replace independent verification or human review.

The shipped example demonstrates the report format using synthetic report shapes; it is not
evidence of real-world time or cost savings. See the
[paired evaluation workflow](https://github.com/Abe-Borg/spec-surgeon/blob/v1.0.0/docs/WORKFLOW_EVALUATION.md)
for collecting representative comparisons.

## Validation and remaining limits

Publication is gated on Linux and Windows suites, Qt and LibreOffice checks, package metadata,
a clean wheel installation, and installed Windows app preview, run, update, reinstall and
uninstall checks. Tests use synthetic documents, scripted provider replies and isolated settings;
they do not exercise the live API or access saved API keys. The latest numbering-render tests
compare all visible tokens while allowing renderer-dependent line and page breaks, and reject
missing, duplicated, changed or reordered numbers and words.

Live-model quality, real-project success rates and Word visual fidelity require separate
evaluation and human review. The Windows installer, wheel and source archive are listed in
`SHA256SUMS`.
