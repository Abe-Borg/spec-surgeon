# Spec Surgeon 1.1

Spec Surgeon v1.1.0 includes the latest merged template compatibility, reliability
and continuous recovery changes since v1.0.0, including PRs #37, #38 and #39.

## Installing and updating

- **Existing v0.4.x or later installation:** choose **Help → Check for updates…**,
  then **Install now**. The app verifies the installer, installs the update and
  reopens, retaining settings, library items and results.
- **New installation or v0.3.x:** download `SpecSurgeon-1.1.0-Setup-x64.exe` from
  this release and run it. No administrator rights are needed.
- **Python:** install `spec_surgeon-1.1.0-py3-none-any.whl` from this release;
  add `[gui]` for the desktop window and `[agent]` for Claude. Built-in workflows,
  saved recipes, library items and specification QA audits work without an API key.

## Approved outcomes and reliable delivery

**File → Built-in operations…** exposes all 50 deterministic operations with
searchable inputs, behavior, limits and verification details. The four guided
workflows remain available without an API key.

Ordinary natural-language edits now propose an independent outcome review. Inspect
each document's targets, resolve ambiguous choices and approve the exact review
before Run. Delivery checks the original-to-final result against those approved
effects as well as the editing recipe. Unsupported outcomes pause for clarification;
explicitly loaded recipes retain their documented recipe verification scope.

Preview approval pins source and auxiliary input content. Selected-document scope,
input/result overlap checks, stale output cleanup, chain delivery after source
saves, and text-edit preservation checks have been corrected. Retries retain the
approved contract and exact target choices. Reports distinguish performed checks
from N/A and automated rendering from human visual acceptance. Generated transforms
have bounded process resources, and incomplete model streams fail visibly.

For noninteractive `do`, `--yes` does not approve an unseen outcome review. Inspect
the saved `outcome-review.json` and use its exact digest with `--outcome-review`
and `--outcome-approval` as described in the
[review flow and CLI examples](https://github.com/Abe-Borg/spec-surgeon/blob/v1.1.0/docs/RELIABILITY.md).

## Continuous recovery and reusable repair methods

Ordinary desktop chat and interactive `do` can continue into reviewed outcome
recovery when the usual methods stop. Failed previews and desktop custom-method
trials feed their evidence into investigation. Answers to recovery and critic
questions resume the existing evidence and ready candidates in the terminal and
desktop. Custom generation still requires the outcome review first; verified
copies follow the existing review and export path.

Successful governed generated methods can be remembered locally and tried on
related jobs with fresh source bindings, targets and independent verification.
Rejected implementations are blocked from reuse. Memory controls can inspect,
disable or forget these records; stored method source may contain project text.
Paragraph borders and shading join the independently checked outcome vocabulary.

See [continuous recovery and repair reuse](https://github.com/Abe-Borg/spec-surgeon/blob/v1.1.0/docs/CONTINUOUS_RECOVERY.md)
for supported flows, scripted cold/warm comparisons and current limits.

## Automatic template style compatibility

Header/footer templates now reconcile document-local style identifiers across
Word languages. Default roles, names and linked character styles identify compatible
styles; incompatible definitions and unrelated ID collisions receive private IDs.
Imported references and inherited formatting are independently checked without
rewriting existing destination definitions or the template. Word's inert built-in
style behavior is preserved.

Agents can inspect the mapping before submitting a job. Approved generated repairs
receive content-pinned templates as immutable in-memory inputs, with instructions
describing the supported independently verified outcomes.

See [template compatibility and recovery](https://github.com/Abe-Borg/spec-surgeon/blob/v1.1.0/docs/TEMPLATE_STYLE_RECOVERY.md).

## Packaging, validation and limits

Worked EditSpecs ship in the wheel and frozen app with source-equivalent compiler
prompts. Installer publication verifies the exact tag revision and keeps existing
versioned installers immutable. Checksum repair is recoverable after interruption.
The Windows installer, wheel and source archive are listed in `SHA256SUMS`.

Publication is gated on Linux and Windows suites, Qt and LibreOffice checks,
distribution metadata, a clean wheel installation, and installed Windows app
preview, run, update, reinstall and uninstall checks. Regression coverage uses
synthetic Word documents, local rendering and scripted/offline provider responses.
It does not establish live-model quality, customer-project success rates or
human-accepted Microsoft Word appearance. Recovery still requires supported
independent outcomes and sufficient resources. Use the
[paired evaluation workflow](https://github.com/Abe-Borg/spec-surgeon/blob/v1.1.0/docs/WORKFLOW_EVALUATION.md)
and human visual review on representative batches for those measurements.
