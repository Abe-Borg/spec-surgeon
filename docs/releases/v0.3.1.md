# Spec Surgeon v0.3.1

Fixes from the independent audit of the v0.3.0 work (`docs/audits/2026-10-14_v0.3.0_independent_audit.md`). No new
operation; several safety nets tightened and two of the v0.3.0 operations widened for messy documents.

## Verification

- V4 now fails on any revision id, of any kind, that is used more often in the output than in the source. The split
  `w:rPrChange` copies written by `replace_text` with `allow_tracked_format_split` were correct, but a wrong copy that
  kept the original id used to pass.
- The compiler's dry-plan gate treats every non-fatal refusal as pattern-sensitive: a spec that plans on none of the
  batch's structure patterns, or an empty batch, is rejected with each file's refusal instead of being accepted and
  setting every file aside.
- `expect` entries refuse `min > max`, negative bounds and misspelled revision kinds.

## Delivery

- An output that fails any check is moved from `outputs/` to `failed/` before delivery. `outputs/` holds only files
  that passed; the batch report, the CLI summary and the window name the `failed/` folder, and the set-aside report
  explains `verify-fail` and nine more refusal codes in plain English.

## Operations

- `replace_text` `ignore_formatting_noise`: `w:cs`, `w:eastAsianLayout` and `w:snapToGrid` are no longer treated as
  noise (they change what the reader sees); the inert proofing markers are removed only between runs that merge.
- `insert_paragraph` `formatting: "inherit"` (default): the new paragraph copies the anchor's paragraph properties and
  the run properties of the anchor's first text run, never its section break or pending revisions; V10 re-derives both
  from the source anchor independently. `formatting: "none"` is the v0.3.0 behaviour.
- `delete_paragraphs` tracked mode accepts paragraphs holding bookmark anchors (Word's `_GoBack`) and proofing markers.
- Template fills keep the document's own characters (a non-breaking space stays a non-breaking space); whitespace
  normalisation serves matching and consensus only.

## Compiler

- The op catalog documents the fill-rule grammar (`literal`, `regex`, `paragraph_after`, `first_match`, whitespace
  handling) and the `expect` syntax including ranges, and ships a worked example for a mixed batch
  (`examples/specs/apply-header-footer-template-fallback.json`).

## Tests

- `tests/test_audit_fixes.py`: every fix with its planted output defect and, where a definition lives on both the
  transform and verifier sides, a planted implementation defect shared by plan and apply. 189 tests.

## Install

As for v0.3.0 (`docs/releases/v0.3.0.md`) with the v0.3.1 wheel.
