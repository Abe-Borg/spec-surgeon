# Spec Surgeon v0.4.0

A new window, built with Qt, updates from inside the app, and **template specs**: attach a spec from the architect and
make your specs' headers, footers and fonts match it. This release also ships the v0.3.1 audit fixes, which were never
published on their own ([v0.3.1 notes](v0.3.1.md)).

## Installing

- **Coming from v0.3.0 or new:** download `SpecSurgeon-0.4.0-Setup-x64.exe` below and run it (no administrator
  rights needed; it installs over v0.3.0 and keeps your results). v0.3.x has no updater, so this one install is by
  hand.
- **From now on:** Spec Surgeon checks for a new version once a day and offers it in a banner. *Install now*
  downloads it, checks it, closes the app, installs and reopens it. **Help → Check for updates…** checks at any time.
- The installer is still unsigned, so Windows SmartScreen may warn on this first manual install. Updates installed
  from inside the app do not trigger that warning.

## Template specs: match the architect's spec

- **Attach any spec from the architect** (or another firm) as the *Template spec* on the Files step — no need to
  prepare it with highlights or placeholders.
- **"Make the header and footer match the template spec":** every one of your specs gets the architect's header and
  footer. Where the architect's header or footer shows its own section number and title (say "08 71 00" and "DOOR
  HARDWARE"), each spec gets its own ("21 13 13", "WET-PIPE SPRINKLER SYSTEMS"). Everything else — firm, project,
  phase, logo, page number — is copied as it is, and tab stops are adjusted to your page width.
- **The architect's number never ends up in your specs.** If their header shows the number or title in another form
  ("087100", "08-71-00", run into other text) or through a Word field, the file is refused with a plain explanation
  instead of being copied. The preview lists every place a value will be replaced, marked like
  «SECTION ⟦08 71 00⟧ – ⟦DOOR HARDWARE⟧».
- **Replacing other words of theirs:** you can also have the architect's phase ("100% CONSTRUCTION DOCUMENTS")
  replaced with your own approved words.
- **"Match the font of the template spec":** your specs' text takes the template spec's font *and size* — for example
  Arial 10 pt for text that is 9 pt today — while text in other sizes (smaller headers, a larger note) keeps its
  size. Symbol fonts (bullets) are never changed. Every run is checked afterwards.
- Claude is told what the template spec is: its own section number and title, where its header and footer show them,
  and its body font and size. Two new example chips start these requests, and two ready-made example specs (with an
  example architect's spec) can be loaded without an API key.

## The window

- **Four steps** on the left: **Files → Describe the change → Preview → Run & results**. Each step shows whether it
  is done.
- **Files:** drag a folder in, or browse. The window counts the Word files it will process and leaves out the
  template spec, even when it sits in the same folder.
- **Describe the change:**
  - Click an example to fill in the request, or load a saved spec.
  - Claude's questions appear in their own **Answers** box.
  - The options are explained where you choose them.
- **Preview:**
  - Tiles count the files, the files that plan cleanly, the exceptions and the structure patterns.
  - The assumptions to check are shown first.
  - A table shows every file, with an "exceptions only" filter.
  - The sample files show their before/after pages; click a page to zoom.
- **Run & results:**
  - Choose copies (the default) or guarded write-back.
  - A progress bar shows how many files are done.
  - PASS / FAIL / EXCEPTION tiles and a results table. Double-click a file to open its edited copy or its
    verification record.
  - **View report** opens the batch report inside the app.
  - **Load set-aside files** and **Advise on exceptions** are on the results page.
- **Run stays disabled until the preview is current.** Changing the folder, the template, the request or the
  answers after a preview means you must preview again. The engine's approval token still guards the files
  themselves.
- **Errors appear on the step that caused them**, in plain words. The activity log, collapsed at the bottom, holds
  the details.
- **Light and dark** follow your Windows setting, or can be chosen in Settings. The window is sharp on high-DPI
  screens. It uses your Windows accent colour.
- **Settings are remembered:**
  - The folders, the last request and the window size are remembered between sessions. Writing back over the
    originals and AI-written transforms are switched off again at every start.
  - **The Anthropic API key** can be remembered in Windows Credential Manager (Settings → "Remember on this
    computer"). It is never written to the settings file.

## Updates: what is checked

- **The check** is one HTTPS request to GitHub's releases API, with the app version in its User-Agent. Nothing
  about your files or projects is sent.
- **The download is accepted only if all of these hold:**
  - the installer has exactly the release's name, `SpecSurgeon-<version>-Setup-x64.exe`;
  - its SHA-256 matches the release's `SHA256SUMS`, and GitHub's own checksum when GitHub reports one;
  - its size matches.

  Anything else deletes the download. The file is hashed again just before it runs.
- **What these checks protect against:** corruption, truncation and a mangled download. They do not protect
  against someone taking over the GitHub account; signing the installer would, and the updater has a place for
  that check.
- **Updates never start while a Preview or Run is in progress**, or while another Spec Surgeon window or command is
  open. Setup waits for the app to close before it replaces any file, and runs without administrator rights.
- **Turning the check off:** Settings → Updates, or set `SPEC_SURGEON_NO_UPDATE_CHECK=1`.
- **Copies installed with pip** are told how to update with pip instead.

## Other changes

- The packaged app includes the Windows support needed to read keys saved in Credential Manager.
- The window's run summary no longer says "written back" for edited copies: copies are listed with their output
  path.
- The installer replaces the program's runtime folder on every install, so files an older version shipped do not
  linger. The uninstaller removes downloaded updates; your settings and results stay.
- Python packaging: the window needs the new `gui` extra (`pip install "spec-surgeon[gui]"`). Without it,
  `spec-surgeon-gui` explains how to install it. The command line needs no Qt.
- The installer is about 15 MB larger because of Qt.

## Tests

- New tests cover the updater (no network), the settings, the window's tables and progress, the Qt window itself
  (offscreen) and the names the app and installer share.
- Template specs and font sizes: the architect's header/footer with each spec's own values, every refusal, look-alikes
  that must be left alone, sizes changed only where they should be, and planted defects (wrong outputs, and wrong
  implementations shared by plan and apply) that the independent verifier must catch.
- On Windows, the installed-app check now also:
  - drives the Qt window;
  - downloads and verifies an installer from a canned release, and rejects a tampered one;
  - performs a real in-app update and confirms the app reopens.
