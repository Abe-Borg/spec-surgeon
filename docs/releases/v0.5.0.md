# Spec Surgeon v0.5.0

Talk a request through with Claude, review the before/after pages, and keep named recipes and custom
operations for the next project. This release includes everything merged since v0.4.1: the reworked
window, detailed diagnostics, the external-audit fixes and both passes of the Phase 8 review fixes.

## Installing and updating

- **From v0.4.x:** choose **Help → Check for updates…**, then **Install now**. The app verifies the
  installer, closes, installs the update and reopens. Existing settings and results are kept.
- **New installation or v0.3.x:** download `SpecSurgeon-0.5.0-Setup-x64.exe` from this release and run it.
  No administrator rights are needed.
- **Python:** install `spec_surgeon-0.5.0-py3-none-any.whl` from this release; add `[gui]` for the window
  and `[agent]` for Claude. The deterministic engine still works without an API key.

## New workflows

- **A conversation about the change.** Reply to questions and refine a preview in the window or an
  interactive `spec-surgeon do` session. When a built-in operation cannot do the request, Claude can offer
  alternatives or a custom transform. Suggested wording reaches a document only after you choose the
  option showing those exact words.
- **A real preview for custom transforms.** The writer receives the conversation and can inspect sample
  XML. A custom transform is tested, verified and previewed before Run; it delivers edited copies only.
  Changed inputs or a changed Render pages setting require a fresh preview.
- **Claude's visual check.** With Render pages enabled, Claude can inspect source pages in the conversation
  and review preview samples' before/after pages. A blocking finding needs your acknowledgement for that
  preview. The visual check is advisory; V1–V10 still decide whether an edited file passes verification.
- **Your library.** Save a previewed spec as a named recipe or a passing custom transform as one of your
  operations, then reuse it on another project. Open **Your library…**, use `spec-surgeon library`, or use
  `do … --save-as NAME`. The library stays on this computer.
- **Streamed Claude calls and visible cost.** The window and terminal show the conversation's accumulated
  token usage and estimated cost; every Claude call uses streaming with a 64,000-token output cap.

## Window and diagnostics

- The four-step window has a status rail, an action bar explaining what each step still needs, a folder
  drop zone and an API-key source indicator. It follows Windows' light/dark setting; Settings contains the
  results folder and API key. Update checks run daily.
- Failures identify the stage, specific reason and sequence of events in `DIAGNOSTICS.md`, per-file traces,
  the run log and verification records. Double-click a result or use `spec-surgeon diagnose` for details.
  **Help → Save diagnostics bundle…** includes the session's compile, conversation, preview and custom
  transform history alongside its run records. Bundles exclude documents, but records can quote their text.
- Worker crashes are isolated and retried in a fresh process. Rendering and comparison errors are recorded
  per file; an engine defect is reported as an internal error with its traceback.
- The project now includes the MIT license and **Help → About Spec Surgeon**, with author, component
  licenses, links and local file locations.

## Safety and correctness fixes

- Output names are unique across a batch, including same-named files in different folders. Delivery checks
  the hash of the verified bytes; inputs inside the results folder are refused before anything is written.
- Template slots in field results are refused; removing a cover footer refuses a footer shared with body
  sections; continuous page numbering clears restarts in every body section. Field protection spans whole
  complex fields, and conflicting paragraph spacing properties are caught during planning.
- The compile gate tries other files when a pattern's representative refuses. Unreadable advice inputs and
  malformed profiles no longer stop unrelated files; a model client is built only when advice needs it.
- Conversation and visual-review responses of the wrong shape are handled without breaking the workflow.
  Suggested wording containing invisible characters is refused. Same-named samples remain distinct.
- Preview approval is checked again immediately before running, including custom transforms. Files changed
  during transform generation require another trial and preview. Session records and buttons follow the
  current preview, and replies invalidate the previous approval.
- Generated code has a tighter module/attribute whitelist and an audit hook. The prototype sandbox is not
  an operating-system security boundary; custom transforms remain subject to copy-only delivery and the
  independent verifier.

## Command-line changes

- `spec-surgeon ask` and `spec-surgeon agent` are retired. Use `do` for requests and `advise` for exceptions.
- The **Allow AI-written transforms** checkbox is removed. Custom transforms are offered within the
  conversation when built-in operations cannot satisfy the request.
- Scripted `do` remains non-interactive: answer questions with `--answer`; a blocking visual review needs
  `--ack-review`. Interactive sessions let you reply and choose alternatives at the terminal.

## Validation and remaining limits

The release workflow gates publication on the full Linux suite with Qt and LibreOffice, package metadata
and clean-wheel installation checks, Windows tests, and the installed Windows app's preview, run and update
checks. Tests use scripted Claude responses and isolated settings; they do not call the live API or touch
your saved API key. Live Claude behavior, real-project sweeps and Word COM rendering still need validation
on the target machine. The installer, wheel and source archive are listed in `SHA256SUMS`.
